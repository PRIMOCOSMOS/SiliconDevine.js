SiliconDevine.js 使用说明

在 IDE 中写普通 PyTorch 模型，导入项目即可开始查看结构。应用会尝试推断并验证示例输入；输入尺寸暂时无法确定时，仍可查看已确认的结构。推荐先用启动器连接代码；后续保存文件，网页会自动更新。

1. 准备环境

  • 保留 D:\SiliconDevine.js 整个文件夹，EXE 需要其中的网页资源与 Python 工具。
  • 模型运行环境需要 Python 3.10+、PyTorch 2.6+ 和模型自身依赖。本机已验证环境为 D:\Anaconda3\python.exe，PyTorch 2.9 CPU。
  • 使用已打包应用无需 Node.js。首次在模型所用的 Python 环境安装本地接口：
D:\Anaconda3\python.exe -m pip install -e D:\SiliconDevine.js\python

若使用虚拟环境，将命令开头换成该环境的 python.exe。Transformers 示例额外需要 transformers==4.57.1；普通 MLP/CNN 无需此依赖。

2. 推荐：直接导入模型项目

  1. 打开 SiliconDevine.exe，点击「导入目录」选择模型所在项目；也可通过「选择文件…」多选 .py 文件。
  2. 选择装有该项目依赖的 Python 环境。高级设置保留 auto。
  3. 点击「进入模型空间」。应用查找 nn.Module 子类及其本地依赖，判断哪个类组合了其他子模块，再捕获真实计算图。
  4. 在 IDE 中编辑并保存。模型目录、包内依赖或配置变更后，网页自动刷新；失败时保留上一份有效图。

无需固定文件名，也无需 build_model()。除了模型类，也会发现直接返回模型实例或先构造后返回局部模型变量的普通函数，函数名不限；函数内部的任意动态构造仍可能需要显式入口。保持原仓库的文件夹和相对导入关系即可。可以先导入附带的 examples/project_model：模型与残差块在不同文件中，不含工厂函数。

默认先尝试 torch.export，失败后尝试实际执行路径，最后尝试 FX。常见全连接、卷积、Embedding、原生多头注意力的输入会从模块属性推断，并通过一次真实 forward 验证。卷积示例空间尺寸依次尝试 8、16、32、64；这只是可执行的示例尺寸，不能据此推断原论文训练设置。网页「模型来源」会注明是否使用了自动推断输入。

项目中与输入名称一致的形状字典也会作为候选依据，例如 {"signal": (batch, n, 3)}。应用只读取这些声明；符号维度用小尺寸示例尝试，并执行原始 forward 验证。相互冲突的声明不会直接采用。

尺寸无法确定时，无需为了打开结构图先写配置。 应用优先显示 FX 能确认的源码依赖，尺寸标为 ?。若数据条件使 FX 也无法展开，则显示已注册模块的所属关系，保留 Python 函数、调用、条件和循环信息；此时不绘制猜测的数据流，不生成虚构的数值动效。需要实际数值时，再按下方方式补充一组示例输入。

总览按源码作用域和实际模块调用分组。点击模块查看组成；「数学结构」展示向量、矩阵与功能单元。右侧说明保留捕获调用的源码位置。模型类名和属性名用于标注，不作为识别某种模型的规则。

显示层级有三个选项：

  • 功能架构：查看模块组成与数据通路。
  • 数学结构：查看投影、点积、门控、注意力、归一化和残差等设计内容。布尔取反、掩码准备、类型转换和内部布局整理不再占用独立架构层；其真实计算归入相关数学单元。点击单元聚焦并查看说明。
  • 底层调用 · 调试：查看完整捕获步骤，包括布尔取反、填充、重排和校验。需要核对实现时再打开。

点积需要同时有相乘与向量轴求和的依据。单独的通道乘积保留乘积或门控含义；残差需要拓扑与形状证据。权重、偏置和真实张量始终可追溯。源码辅助函数的实际调用范围也用于分组，导入的多文件函数采用同一规则。

工程步骤的隐藏只改变显示。因果注意力的可见范围、有效数据条件、专家路由等有数学意义的约束仍属于对应模块；特征拼接、特征分组及空间特征向量化也会保留。高斯分布显示均值和方差的数学含义，参数广播不单独展开。

查看模型输入

点击画面上方「模型输入」，打开右侧说明。这里列出原始 forward 签名、必需与可选参数、默认值、张量类型、嵌套结构及源码用途。3D 中的输入使用源码参数名；字典和列表保留路径，例如 samples['images'][0]。

  • [1 × 8 × 3] 是本次实际捕获的尺寸；[batch × n × 3] 是源码形状声明，并附来源位置。示例尺寸不代表训练尺寸。
  • ? 表示尚未确认；应用继续显示能确认的源码结构。
  • 对 valid=None 等可选参数，若源码明确写出了生成逻辑，面板会列出默认表达式及其依赖输入。
  • 数字、布尔开关和字符串也列在接口中。只执行了一条动态分支时，说明与图均对应这次捕获。
  • 旧 JSON 没有函数签名信息时仍可使用；重新导入源码即可得到完整输入说明。

3D 标注是结构近侧的悬空文字，没有水晶底板；位置和朝向固定在模型空间中。转动模型时文字与结构一起转动。仍可切换全部、按需或隐藏标注。

模型需要参数、多个候选或特殊输入时

应用先自动查找入口，读取源码中的构造调用、配置类默认值和输入示例，再结合 PyTorch 模块约束验证输入。能确定的内容直接采用，正常导入无需填写表单。输入尺寸暂时未知时，先展示可确认结构，仍可继续浏览。

只有自动解析仍无法继续时，界面才提示尚未解决的问题。点击「确认未确定的入口」或「补充未确定信息」进行排查：

  1. 入口存在真实歧义：只确认目标类，后续构造参数和输入仍由应用继续解析。
  2. 缺少构造信息：只补充无法从源码或默认值确定的参数；已确定的参数保留。
  3. 指定输入未通过验证：调整该输入的尺寸、类型或内容，也可恢复自动推断。Token ID 的随机整数上限应小于或等于词表大小。
  4. 点击 「应用并重新捕获」。网页地址保持不变，完成后自动更新。失败时保留上一份有效模型。

「模型库 → 连接本地 IDE → 导入排查」保留主动检查和覆盖设置的入口；正常使用无需打开。源码中存在冲突的构造配置时，应用会明确保留歧义，不按类名或参数量随意选择。

输入尺寸用 1, 3, 32, 32 这样的形式填写。字典、列表和配置对象通过字段控件组合，不需要编辑 JSON。示例输入单个最多 200 万元素；实际计算默认预算为 2500 万参数与缓冲元素。「捕获与内存设置」可修改捕获接口和预算。未带字段类型的特殊第三方配置对象仍可能需要仓库原有的构造函数。

故障排查中补充的设置按项目保存在 %LOCALAPPDATA%\SiliconDevine\import-profiles，再次导入时沿用。原有 silicondevine.json 和启动器「导入旧配置…」继续兼容，用户设置优先。自动发现的旧配置损坏时会记录原因并继续解析源码；主动指定的配置无法读取时才提示排查。

出现问题时

界面提示 处理方式
缺少依赖 查看缺失模块和当前 Python 路径。点击启动器「切换环境」，或复制提示的安装命令到对应终端执行，再重试。应用不会自动安装。
项目导入路径不完整 选择包含该包的仓库根目录，保留原目录结构。

完整错误保存在「技术详情」或启动器「运行日志」中，日常处理先看问题标题和对应操作。

自动导入运行构造器与前向过程，应使用你信任的模型项目。静态扫描不执行仓库脚本；捕获会正常导入选中类及其依赖，因此这些文件的顶层代码仍会运行。不会自动安装依赖、下载检查点或启动训练；权重为构造器初始化状态。要加载现有权重，可继续使用下面的显式入口。

自动化范围：支持普通 PyTorch 包、相对导入、跨文件继承、子模块组合，以及可通过本地绝对导入确定根目录的命名空间包（没有 __init__.py）。动态注册产生的类、无法定位根目录的命名空间包、需要设备/外部资源的构造器、无法进行 meta 预检的模型，以及自定义编译算子可能需要明确入口或适配。多个独立候选不会擅自任选；缺少配置时也不会伪造架构。execution 记录本次输入实际经过的路径，不包含未执行分支。

导入 MMHVAE 的 network 目录

总览中的并行编码分支采用环形立体塔。四座编码塔分别对应 US、T2、CET1、FLAIR，每一层是该模态对应 Block 的真实输出；编码路径向上压缩，中心生成路径向下展开。各自的后验概率头独立显示，图中连线保留原来的调用与参数共享关系。点击塔身或概率头继续展开。

概率头用均值 μ、方差 σ²说明分布。MMHVAE 源码实际预测对数标准差 ℓ，再通过 σ²=exp(2ℓ) 得到方差；传给 PyTorch Normal 的第二个参数是标准差 σ。概率图展示坐标 0 的实际均值和方差，曲线横轴覆盖 μ±3σ、纵轴为归一化密度。PoE 说明保留仓库按标准差倒数融合的实际公式。编码 Block 与解码 Block 按源码分别展示，前者为双卷积残差结构，后者含扩张与深度卷积。

重新导入后，默认进入「功能架构」：四个模态编码分支 → 顶层概率编码与 PoE → 六级条件潜变量生成 → 四个图像解码分支。点击模块继续展开，右上角「上一级」返回。编码残差块内显示实际 InstanceNorm、SiLU、卷积、通道注意力和残差相加；权重与偏置沿用基础算子的显示方式。

模块索引只列出总览和当前层的入口。切换「底层调用 · 调试」可查看该模块全部捕获步骤，包括架构视图收起的校验分支。分组依据是 Python 源码位置、实际函数调用、已执行的循环和 PyTorch 模块路径。旧 JSON 不含新增的调用边界信息，需要重新导入源码目录；已有的矩阵和注意力识别仍可使用。

选择 D:\WUDAN_RESEARCH_1\MMHVAE\network，高级设置保持 auto，入口和配置文件留空。应用会静态读取仓库 inference.py / train.py 中的 argparse 默认参数和主模型构造调用，不运行训练或推理脚本。对于可确定的默认条件分支，自动选择对应模型并生成多模态字典输入；来源文件、行号和实际构造参数保存在网页「代码来源与识别依据」中。

当前仓库默认选择 network.mhvae:MHVAE2D，使用 us / t2 / cet1 / flair 四模态，空间尺寸 192×192、6 次下采样、7 级潜变量；可视化示例 Batch 为 1，权重由原始构造器初始化，未自动加载 pretrained 检查点。该模型的运行时断言不能直接通过 export，因此会回退到 execution。未支持的算子保留真实输入输出边界。

普通仓库也可复用这一机制：只解析字面量默认参数、简单条件和构造器关键字参数。不能唯一确定时，通过导入表单选择和补充。表单设置优先；保存代码、修改设置或点击重试均会触发重新捕获。Windows 日志统一使用 UTF-8。

PyTorch 捕获本身需要模型实例和示例输入，接口边界见 torch.export；无存储的参数尺寸预检使用 meta device。

显式构造：精确控制输入和权重

新建 D:\MyModels\my_model.py，复制以下完整示例：

import torch
from torch import nn

class Encoder(nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = nn.Sequential(
            nn.Linear(16, 24), nn.GELU(), nn.Linear(24, 8)
        )

    def forward(self, x):
        return self.layers(x)

def build_model():
    torch.manual_seed(42)
    model = Encoder().eval()
    x = torch.randn(2, 16)  # Batch=2，每项16个特征
    return model, (x,)     # 一个输入也要写成元组，注意逗号
  1. 双击 D:\SiliconDevine.js\SiliconDevine.exe。
  2. 选择刚保存的文件，以及安装了模型依赖的 python.exe。
  3. 高级设置：工厂函数填 build_model；这个示例选择 fx。
  4. 点击「进入模型空间」。浏览器自动打开后，修改代码并保存即可刷新。

框架运行一次前向计算，记录本次输入对应的形状与数值。已有权重可在 build_model() 返回前通过 load_state_dict() 加载。工厂函数中不要启动训练、启动服务或调用 show()。

更换文件或环境前，先停止服务。捕获失败时保留上一份有效图，错误会显示在界面上；修正代码并再次保存即可。

多输入、关键字参数与捕获设置

args 对应 forward 的位置参数，kwargs 对应关键字参数。下面是工厂函数的另一种返回格式；model、x、context、mask 使用你实际创建的对象：

return {
    "model": model,
    "args": (x, context),
    "kwargs": {"attention_mask": mask},
    "options": {
        "backend": "execution",
        "include_values": True,
        "value_limit": 4096,
        "snapshot_budget": 64 * 1024 * 1024,
    },
}

文件中的 options.backend 优先于启动器选项。输入尺寸、类型和设备必须与模型匹配；例如嵌入层通常接收整型 Token ID，卷积通常接收 [B,C,H,W]。

3. 选择哪种捕获接口

接口 适合的情况 要点
fx 普通 MLP、CNN、自定义 nn.Module 先从这里开始，保留模块边界；依赖输入数值的 Python 分支可能无法跟踪。
export 需要函数化 ATen 图、声明动态形状约束 使用 torch.export；不支持的控制流会报错。dynamic_shapes 只用于此接口。
execution MoE 等依赖实际路由的代码、选定 LLM 子模块 使用 make_fx 记录本次执行路径；输入改变后需重新捕获，不包含未执行分支。

三种接口都会实际执行模型。导出器复制模型与输入，以 eval 模式捕获，并恢复随机数状态；它展示前向计算，不展示训练反向传播。自定义 C++/CUDA 算子或特殊容器可能仍需适配，导出失败时先缩小到相关子模块排查。

4. 直接从正在写的 Python 程序打开

无需工厂函数时，在模型与示例输入准备好后调用：

from silicondevine import show

show(model, (x,), backend="fx")

终端会打印本地网页地址，打开该地址即可。此调用默认阻塞，结束时按 Ctrl+C。show() 不监视文件；保存自动更新使用启动器或下一节的 watch。

需要自己控制生命周期：

server = show(model, (x,), backend="execution", block=False)
try:
    server.update(model, (new_x,), backend="execution")
    server.wait()
finally:
    server.close()

不使用启动器也能监视文件：

D:\Anaconda3\python.exe -m silicondevine.watch D:\MyModels\my_model.py --backend execution --static-dir D:\SiliconDevine.js\demo-dist

监视器同时检查模型目录中的 Python 文件及导入设置。建议给模型建立独立目录；保存代码或提交表单后自动更新。默认端口为 5182，被占用时添加 --port 5183。启动器会自动寻找空闲端口。

5. 导出 JSON，离线查看或分享

from silicondevine import export_model

export_model(
    model, (x,), "my-model.sd.json",
    backend="execution",
    include_values=True,
    value_limit=4096,          # 单个张量保存的连续元素上限
    total_value_limit=500000,  # 本次JSON保存的数值总量上限
)

网页打开「模型库 → 导入模型 JSON」，选择文件。也可运行项目中的 start-demo.cmd 打开预构建网页；无需启动 IDE 服务。

export_model() 默认不包含数值，想看数值配色与计算结果应设置 include_values=True。导出的窗口之外只保留形状；离线 JSON 无法读取未保存的值。IDE 服务可按需读取快照中保留的坐标，默认快照预算 64 MiB。

  • 数据晶体表示可见坐标处的实际数值；权重矩阵使用不同材质。全连接的权重线与同一 W 元素联动。
  • 模块边界用开口角标和后侧轮廓线表示。全连接的 W、b、输出，卷积核与偏置，以及归一化参数和运行统计量都有明确归属。原始算子视图中的已识别注意力缩放、掩码、Softmax 链也具有共同边界。
  • 点击选中模块后，所属张量、参数、计算连接与相关标牌一起突出，其余结构减淡。共享输入保留原位置并参与高亮；取景优先容纳本模块与近侧输入，远处共享输入可沿连接追溯。按「总览」解除选择，恢复自动轮播。
  • 数值颜色按当前张量已知数值的范围归一化；跨张量的相同颜色不保证数值相等。
  • 注意力主干保留投影、位置编码、相似度、概率分配、Value 汇聚与输出投影。缩放、掩码、Softmax 可聚合为一个功能段，点击后查看原始步骤。
  • 按头组织将通道分成 Head × 每头通道；Key 对齐交换 Token/通道轴以计算 QKᵀ；合并多头恢复每个 Token 的完整通道。晶体重排与共享展开用于说明坐标变化，元素数值保持不变。
  • 全息标注固定在对应张量近侧，位置和尺寸不随镜头重新排位，文字朝向镜头。按需模式在总览控制数量，选中后展开该功能模块的关联标牌；全部／隐藏开关仍有效。未选中时，悬停权重、偏置或运行统计量可优先查看具体张量。
  • 函数图象中的输入点位于 x 轴，输出点位于对应曲线上；刻度、曲线和投影线共用坐标。曲线颜色表示函数值。
  • 界面播放的动效用于解释捕获的数值与依赖，播放速度不等于实际计算耗时。

张量尺寸来自代码。要改变自己模型的 Batch、通道或 Token 数，请修改输入和模型代码，再保存；网页里的参数控件只用于支持重建的内置示例。

旋转、平移和缩放

  • 左键拖动旋转；右键或 Shift + 拖动平移。点击工具栏「平移」后，左键也用于平移，再点一次恢复旋转。
  • 滚轮／双指捏合围绕当前观察中心缩放。触屏单指旋转，双指可同时平移和缩放；「平移」模式支持单指平移。
  • 「视角」可选正视／立体，保留观察中心和缩放距离；「总览」或 Home 恢复完整取景。
  • 先点击三维画面，再用方向键平移、Shift + 方向键旋转、＋／－缩放。全屏下也可用这些快捷键。
  • 点击模块聚焦。拖拽、右键操作和双指手势不会触发模块点击；手动操作会中止正在进行的自动镜头移动。

7. 大模型：先看结构，再看真实计算单元

模型库提供 DeepSeek-V3、GLM-4.5、MiniMax-M1。总览按原配置表达重复层和专家组；点击后查看代表性 Decoder 的执行图，再进入 Attention、MoE、专家或基础算子。

内置执行图来自参考实现的原始 forward，使用缩小维度、固定种子、未训练权重。不同层级共享捕获张量 ID。它们不是完整检查点推理：DeepSeek 使用 Transformers 的展开式 MLA；MiniMax Lightning 使用原始 decode 分支并作 CPU 接口适配。实现来源与边界 中有具体说明。

对自己的大模型，可选两种方式：

  • 只查看支持家族的完整配置：使用 architecture_from_config(config, family)，适配器为 deepseek_v3、glm45、minimax_m1。见 配置结构接口。
  • 查看实际计算：选择能在本机运行的子模块和小输入，交给 export_model 或工厂函数；若要观察已有权重，自己加载对应权重。框架不会自动缩小任意模型。

显示预算只限制绘图开销，不限制 PyTorch 执行内存。大模型的复制、加载与前向计算仍可能占用大量内存；无须为查看内置示例下载完整权重。

怎样阅读多分支模型

默认先打开功能架构。互不依赖的分支可排成环形计算塔；每层水晶对应实际中间张量。点击塔进入内部模块，再用「数学结构」查看设计细节；「底层调用 · 调试」保留完整执行节点。

银白边界标出结构归属，淡黄色提示当前选中区域。权重与数据的托板颜色有所区分，水晶内部颜色仍表示数值。卡片固定在结构近侧；可用「按需标牌／全部标牌」调整可见数量。

修改代码后需要重新捕获，旧 JSON 不会自动生成新增的源码分层信息。若缺少源码或模型依赖输入动态选择路径，图只表达本次能够确认的调用和分支。

8. 常见问题

现象 处理
找不到 silicondevine / torch 确认启动器选中了正确 Python；在该环境安装依赖与本地接口。
网页打开但没有模型 按问题提示选择入口或补充参数；已有工厂入口需要返回 (model, args)。
FX 报控制流错误 改用 export；若依赖实际输入选择分支，用 execution 或先导出子模块。
缺少数值或窗口无法读取 导出时启用 include_values；确认 IDE 连接、快照预算及窗口是否被保留。
模块只显示输入输出 查看「解读与参数 → 算子支持检查」；该操作可能需要数学插件。
图太大、文字太多或卡顿 返回功能架构、进入子模块、将标注设为按需，减小输入或可见坐标窗口。
保存后仍是旧图 捕获失败会保留旧图；按界面提示修正并重试，或保存模型代码。
更新后仍看到旧界面 停止旧服务，关闭旧启动器，重新打开项目目录内的 EXE，再刷新网页。

9. 前端集成与继续阅读

把框架嵌入自己的网页：

import { SiliconDevineViewer } from 'silicondevine.js';
const viewer = new SiliconDevineViewer(document.querySelector('#stage')!, {
  maxCells: 8192, cellsPerTensor: 128, maxConnections: 12000,
  labels: 'auto', pixelRatio: 1.5,
});
viewer.load(graph); // graph 为导入的 .sd.json 对象
// 页面卸载时：viewer.dispose();

容器需有高度，例如 #stage { height: 650px; }。库通过本地目录安装，尚未发布到 npm；宿主需使用项目声明兼容的 Three.js 版本。运行项目开发环境用 npm install、npm run dev，构建用 npm run build。

需要更细的资料时，从 文档目录 进入；接口、模型来源、支持范围和验证记录各自独立维护。本页是日常使用的主入口。
